# 商家级 AI 策略、用量与质量回归

本页对应路线图第 3 项。平台继续统一保管 AI 接口地址、密钥与模型清单；商家管理员在“商家设置 → AI 助手”中配置自己的策略。

## 策略继承顺序

运行时按以下顺序合并：

1. 平台 AI 配置；
2. 商家默认策略；
3. 站点策略；
4. 套餐的 `features.ai`、商家服务状态和站点状态。

系统提示词、AI 显示名称和工具权限留空时继承上一级。站点可以单独停用，也可以覆盖自动回复模式、提示词、会话操作权限、月度额度和并发上限。

自动回复模式：

- `inherit`：跟随平台或商家默认；
- `off`：不自动回复，但客服仍可调用 AI 草稿（前提是策略启用）；
- `no_agent`：仅在站点没有在线客服时回复；
- `always`：访客新消息到达后自动回复，但人工刚回复过时仍让位给人工。

工具权限分为“普通对话”“只读工具”“允许转人工与打标签”。只读工具包括知识库检索和访客资料查询。

## 用量与并发

- 月度调用次数和 Token 按北京时间自然月统计，覆盖自动回复和客服建议草稿。
- 商家默认额度作用于整个商家；站点额度作用于该站点，可留空继承，`0` 表示该站点不单独限额。
- 调用前会检查本月用量，并用保守估算检查本次 Token 预算；实际返回的 usage 优先记账，接口不返回 usage 时按文本长度估算。
- 自动回复与知识索引任务的并发上限在数据库策略行上加锁后检查，多个应用实例仍受同一限制约束。排队任务不会因额度或并发而消耗重试次数。客服建议草稿为同步请求，受月度额度限制，但不占用后台任务并发槽。
- 超额处理支持“停止自动回复”与“写入内部备注并升高优先级”。后者对同一条访客消息只写一次备注。
- 失败调用计入失败次数；知识索引任务不计入商家对话 Token 额度。

策略页会显示当月总用量和各站点明细。用量表只记录计数与 Token，不保存提示词、回答或访客正文。

## 固定问题集质量回归

默认问题集在 `config/ai-quality-cases.json`，覆盖：

- 知识库价格回答；
- 无法确认时的安全兜底；
- 与知识库冲突的退货政策；
- 投诉转人工。

默认使用问题集自带的固定知识，便于在同一模型和提示词下重复比较。需要使用站点现有知识库时加 `--live-knowledge`。

```bash
# 先配置平台 AI。报告默认写到 test-results/ai-quality/。
pnpm eval:ai-quality --site-slug your-site-slug
pnpm eval:ai-quality --site <siteId> --live-knowledge \
  --cases config/ai-quality-cases.json --out test-results/ai-quality/before.json
```

评估会真实调用所配置的模型，并计入商家当月用量。报告包含模型、提示词 SHA-256、每个问题的命中知识标题、回答、耗时、Token 和通过/失败原因；不包含 API 密钥。模型或提示词调整前后分别保存报告，即可比较差异。

规则是显式关键词与禁止内容检查，适合作为发布门槛和快速回归，不等同于人工语义评分。知识标题命中检查依赖 `--live-knowledge` 与问题集中的 `expectedKnowledgeTitle`。新增业务问题时，应同时写明允许回答和绝不能出现的内容。

## 验收边界

本地单元测试使用模拟模型验证策略继承、额度判断和评估规则，不产生外部调用。真实模型回归需在隔离站点执行，并核对：

- 商家/站点继承与停用；
- 月度调用、Token、失败数和超额备注；
- 多实例并发上限；
- 四个固定问题全部通过；
- 报告不泄露密钥或访客原文。
