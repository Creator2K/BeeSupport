# BeeSupport · 多站点统一客服系统

把多个网站的客服收进同一个后台：访客端**一行脚本**接入，客服在**独立工作台**实时接待，
消息、会话、留言、通知与统计统一沉淀。

后续改进与逐步实施进度见 [项目改进计划](ROADMAP.md)。

界面风格对标 [linux-do/cdk](https://github.com/linux-do/cdk)：`shadcn/ui (new-york)` + `Tailwind v4` + 中性 zinc 灰阶，
亮色为主、暗色可切，克制、类 GitHub 的社区产品质感。

## 功能一览

**访客端**

- 一行 `<script>` 嵌入，右下/左下悬浮气泡（渐变材质 + 展开/收起动效 + 未读角标）
- 移动端自动全屏，适配 iOS 安全区
- 发起会话前**必填邮箱**（本地持久化，二次访问自动带出昵称/邮箱）
- 图片与文件上传、**Ctrl/⌘+V 直接粘贴截图发送**、输入中提示、已读回执
- 客服不在线（或非工作时间）自动切换为**离线留言**形态
- 会话结束后可提交**满意度评价**；继续发消息可重新开启会话
- 中英双语，跟随浏览器语言

**客服工作台**（`/agent`）

- 三栏布局：会话列表 / 聊天窗口 / 访客信息
- 待接入队列、我的会话、全部会话、已结束，按站点与关键词筛选
- 接入（claim）、转接给同事、结束、重新打开
- 快捷话术（输入 `/` 或点按钮触发，支持 `/shortcut` 快捷码）
- 图片/文件上传，也支持 **Ctrl/⌘+V 粘贴截图**直接发出
- 内部备注（访客不可见）、标签、优先级、主题
- 在线 / 离开 / 离线状态切换
- 未读数、浏览器桌面通知、**5 种提示音可选 + 音量调节**（个人偏好存服务端，换设备也一样）、
  断线自动轮询兜底
- **访客画像**：访问次数、浏览页数、当前/落地页、来源、设备/系统/浏览器、屏幕与视口、时区、
  语言、网络、深浅色偏好、硬件、IP，以及该访客的**历史会话**（点一下直接切过去）

**管理后台**（随机路径 + 仅管理员）

- 入口路径由 `ADMIN_PATH` 决定（默认 `/admin`，建议用随机串，如 `/console-82553547`）；
  直接访问 `/admin` 返回 404，登录后自动跳到该路径
- **站点管理**：多站点即多渠道，接入密钥、域名白名单、欢迎语/离线语、主题色、气泡位置、
  自动分配开关、通知邮箱、工作时间段、一键复制嵌入代码
- **客服账号**：只能在这里手动创建；角色（管理员/客服）、按站点授权、禁用/启用、重置密码
- **会话记录**：全站历史检索、会话详情与完整对话回放
- **快捷话术**：全局或指定站点，团队成员共享
- **AI 助手**：OpenAI 兼容接口（地址 / 密钥 / 模型，可在线拉取模型列表）、**多模型清单**、
  系统提示词、自动回复策略、**工具调用**、**知识库 + 向量检索（RAG）**、连通性测试、
  一键重建向量索引；三个页签（接口与模型 / 提示词与策略 / 知识库）分开，知识库是
  左侧列表 + 右侧整屏编辑器的双栏布局，长内容也写得下
- **通知渠道**：自定义 Webhook（HMAC-SHA256 签名）、Telegram、钉钉机器人、企业微信机器人、
  **微信（扫码登录）**，按事件订阅，可一键发送测试消息
- **微信**：不单独占菜单——通知渠道页顶部就是**微信扫码登录**面板（二维码、状态、配对码、
  默认接收人、测试发送、运行日志），渠道类型只保留「微信（扫码登录）」一项，不用填任何地址
- **系统设置**：SMTP 邮件通知（后台配置优先于环境变量）、个人资料、修改密码
- **操作日志**：关键后台操作留痕

**AI 助手**

- 任意 **OpenAI 兼容接口**：填 `Base URL` + `API Key`，点「获取模型」直接拉模型列表
- **多模型可切换**：把常用模型勾进清单，客服在工作台直接切换（选择按人保存）
- **系统提示词** 定义语气与边界，`{siteName}` 会自动替换成站点名
- **知识库 / RAG**：条目自动切片（约 420 字/片，带重叠），关键词打分召回；
  开启向量检索后走 **embedding + 关键词混合召回**，后台可一键重建索引
- **工具调用（function calling）**：模型可自行调用
  `search_knowledge`（查知识库）、`get_visitor_context`（看访客资料）、
  `escalate_to_human`（转人工 + 置优先级 + 写内部备注）、`tag_conversation`（打标签）；
  每次调用的名称、参数、结果、耗时都会存进消息 `meta`，工作台可展开查看
- 三种自动回复策略：关闭（只做人工辅助）/ 客服不在线时自动回复 / 所有访客消息先自动回复；
  人工正在回复时不会插话
- AI 回复以独立身份入库（`AI` 发送者 + 显示名称 + 所用模型），**不会被误统计成人工首次响应**，
  会话也仍然留在待接入队列里
- 客服工作台有「AI 建议」按钮：结合会话上下文与知识库，生成一条可直接发送的草稿，
  并显示这次用到的工具与知识库命中

| 层        | 选型                                                                 |
| --------- | -------------------------------------------------------------------- |
| 框架      | Next.js 15（App Router、RSC + Server Actions）                       |

## 快速开始（本地开发）

前置：Node 20+、pnpm、Docker（只为起 Postgres/Redis）。

```bash
# 1) 起数据库与 Redis（宿主机端口 55432 / 56379，避免与本地已有服务冲突）
docker compose up -d postgres redis

# 2) 安装依赖并生成 Prisma Client
pnpm install
pnpm db:generate

# 3) 配置环境变量（复制后按需修改，AUTH_SECRET 必填）
cp .env.example .env          # Windows: copy .env.example .env

# 4) 建表 + 初始化演示数据
pnpm prisma migrate deploy
pnpm db:seed

# 5) 启动（必须用这个脚本：实时通道跑在自定义 server 上）
pnpm dev
```

打开 <http://localhost:3000>。**服务启动日志里会打印三个入口地址**（访客脚本 / 客服工作台 /
管理后台）。管理后台是随机路径，例如 `http://localhost:3000/console-82553547`——
改路径就改 `.env` 里的 `ADMIN_PATH`。演示账号（可用环境变量覆盖）：

| 角色               | 邮箱                      | 密码           |
| ------------------ | ------------------------- | -------------- |
| 管理员             | `admin@beesupport.local`  | `ChangeMe123!` |
| 客服               | `agent@beesupport.local`  | `ChangeMe123!` |
| 客服 2（转接演示） | `agent2@beesupport.local` | `ChangeMe123!` |

演示站点：`示例站点`（接入密钥 `demo-site-key`，开启自动分配）、
`文档站`（`docs-site-key`，关闭自动分配，用来演示排队）。

> ⚠️ 生产环境请立刻改掉这些密码，并替换 `AUTH_SECRET`。

## 生产部署（Docker Compose 一键）

```bash
# 1) 准备环境变量
cp .env.example .env
#   至少改这几项：
#   AUTH_SECRET="$(openssl rand -base64 48)"
#   APP_URL="https://support.example.com"
#   POSTGRES_PASSWORD="强密码"

# 2) 构建并启动（app + postgres + redis）
docker compose up -d --build

# 3) 首次初始化演示账号（可选；也可以直接进后台建客服）
docker compose exec app npx tsx prisma/seed.ts
```

访问 `http://<服务器>:3000`；上生产建议前面挂 Nginx/Caddy 做 HTTPS 反代，并把
`APP_URL` 改成 https 域名（会话 cookie 的 `secure` 属性依据 `APP_URL` 协议自动决定，
因此内网 http 部署同样可以正常登录）。

### 反向代理注意

Socket.IO 走同域 `/socket.io`，反代需要透传 WebSocket 升级头：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
}
```

### 数据与备份

| 卷          | 内容                                                |
| ----------- | --------------------------------------------------- |
| `pgdata`    | PostgreSQL 数据目录                                 |
| `redisdata` | Redis AOF（在线状态、限流计数，丢了不影响业务数据） |
| `uploads`   | 访客与客服上传的文件（容器内 `/app/data/uploads`）  |

```bash
docker compose exec postgres pg_dump -U beesupport beesupport > backup.sql
docker run --rm -v beesupport_uploads:/data -v "$PWD":/backup alpine \
  tar czf /backup/uploads.tgz -C /data .
```

### 多实例水平扩展

Redis 已配好 `@socket.io/redis-adapter`，直接横向扩容 app 容器即可（多个实例共用同一
Postgres 与 Redis），实时事件会跨实例广播。未配置 `REDIS_URL` 时退化为单实例模式。

## 访客端接入

在任意网站 `</body>` 之前加一行即可：

```html
<script
  src="https://support.example.com/widget.js?key=demo-site-key"
  async
></script>
```

可选参数：

| 参数       | 说明                                         |
| ---------- | -------------------------------------------- |
| `key`      | **必填**，站点接入密钥（后台站点列表里复制） |
| `position` | `left` / `right`，覆盖站点配置的气泡位置     |
| `color`    | `%23RRGGBB`，覆盖气泡主色                    |
| `label`    | 气泡旁边的文字，例如 `label=在线客服`        |

也可以在页面里用 API 控制：

```html
<script>
  window.BeeSupport = window.BeeSupport || { q: [] };
  BeeSupport.q.push(function (bs) {
    // bs.open() / bs.close() / bs.toggle() / bs.setUnread(3)
  });
</script>
<script
  src="https://support.example.com/widget.js?key=demo-site-key"
  async
></script>
```

**域名白名单**：站点里配置 `allowedOrigins`（每行一个，支持 `*.example.com`）后，
只有白名单内的页面能创建会话；留空表示不限制（建议上线后填写）。

**SPA / 路由跳转**：脚本常驻，刷新页面即可带上最新页面地址；同一访客的会话会自动续接。

**CSP 提示**：气泡与聊天窗都是一个 iframe，站点若有内容安全策略，需要放行：

```
script-src  https://support.example.com
frame-src   https://support.example.com
connect-src https://support.example.com   # 实时通道（WebSocket）也需要
```

## 使用说明

### 客服

1. 打开 `/login` 登录（客服与管理员共用入口，按角色跳转 `/agent` 或 `/admin`）。
2. 右上角切换 **在线 / 离开 / 离线**；只有「在线」的客服会被自动分配。
3. 左侧选择会话，或从「待接入」里 `接入会话`；支持 `转接` 给同事。
4. 输入框里：`Enter` 发送、`Shift+Enter` 换行、输入 `/` 打开快捷话术。
5. 右侧面板可改标签/优先级/主题，写**内部备注**（访客看不到）。
6. 首次进入请点一次「开启桌面通知」，标签页在后台时也能收到提醒；右上角喇叭图标一次点击
   即可静音/恢复，旁边的铃铛按钮里可以换提示音（5 种音色，点一下试听）、调音量、发测试通知。

### 管理员

- `/admin/sites`：新建站点 → 复制嵌入代码 → 填域名白名单与通知邮箱。
- `/admin/agents`：新建客服 → 勾选负责的站点；不勾选则暂时不接待任何站点。
- `/admin/canned`：维护团队话术；`/shortcut` 便于客服快速调用。
- `/admin/webhooks`：钉钉/企业微信机器人直接粘贴 Webhook 地址；Telegram 用
  `https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>`；
  微信只需选「微信（扫码登录）」——页顶的面板里扫码登录后即可推送，接收人可以留空
  （用面板里配的默认接收人）。
- `/admin/ai`：三个页签——**接口与模型**（接口地址、密钥、拉模型、勾选可用模型、工具调用、
  向量检索、索引概况与重建）、**提示词与策略**（AI 显示名称、整屏系统提示词、自动回复策略、
  采样参数）、**知识库**（左侧列表 + 右侧整屏编辑器，支持搜索、按站点作用域、保存即自动重建切片）；
  底部/顶部随时可「保存配置」与「测试连接」。
- `/admin/settings`：配置 SMTP 后可「保存并测试连接」「发送测试邮件」；离线留言与新会话
  会同时发到站点通知邮箱。

Webhook 会校验渠道返回的业务结果：Telegram / 微信桥接检查 `ok`，钉钉 / 企业微信检查
`errcode`；自定义 Webhook 以 HTTP 2xx 为成功。HTTP 408 / 429 / 5xx 和网络异常最多尝试
3 次，永久错误会直接记录失败。每次事件最多并发投递 4 个渠道，解析渠道响应时设置 16 KiB 上限。
邮件与 Webhook 通过持久化 NotificationJob outbox 独立调度；worker 使用数据库租约和 SKIP LOCKED，支持多实例消费、重试与失败记录。

### 微信通知

1. 打开 `/admin/webhooks`（通知渠道），最上面的 **微信扫码登录** 面板点「生成二维码并登录」；
2. 用微信「扫一扫」扫描二维码并在手机上确认；如果微信提示配对码，把手机上的数字填进面板；
3. 登录成功后：把「启用微信通知」打开（服务重启会自动登录；凭证存在 `WECHATBOT_STORAGE_DIR`，
   默认 `${UPLOAD_DIR}/wechatbot`，Docker 里已经在 `uploads` 卷内）；
4. 点「新建渠道」，类型选「微信（扫码登录）」，接收人填 wxid 或备注名
   （例如 `文件传输助手`，方便自测），留空则用面板里的默认接收人；
5. 面板里的「测试发送给」可以直接验证通道。

> 想用独立进程/独立机器跑微信（例如把微信放在另一台电脑上），可以继续用
> `pnpm wechat:bridge` 起一个外部桥接服务，然后在数据库/接口里把渠道类型设为
> `WECHAT`（界面上不再提供这个选项，保留给历史数据与高级用法）。
> 两种方式都是单向发送：只把通知推给你，不处理微信里收到的消息。

## 环境变量

| 变量                                            | 必填 | 说明                                                                           |
| ----------------------------------------------- | ---- | ------------------------------------------------------------------------------ |
| `DATABASE_URL`                                  | ✅   | PostgreSQL 连接串                                                              |
| `AUTH_SECRET`                                   | ✅   | JWT 签名密钥，`openssl rand -base64 48`                                        |
| `APP_URL`                                       | ✅   | 对外访问地址，用于嵌入代码与邮件链接；https 时 cookie 自动加 `secure`          |
| `ADMIN_PATH`                                    | ➖   | 管理后台入口路径，默认 `/admin`；建议改随机串，如 `/console-82553547`          |
| `REDIS_URL`                                     | ➖   | 配置后启用跨实例广播与 Redis 限流；不配置则单实例内存实现                      |
| `SOCKET_IDENTITY_TTL_MS` | ➖ | 身份复核间隔，默认 5000毫秒，上限 60000 |
| `SOCKET_CONVERSATION_TTL_MS` | ➖ | 会话访问缓存间隔，默认 5000毫秒，上限 60000 |
| `PORT`                                          | ➖   | 监听端口，默认 3000                                                            |
| `UPLOAD_DIR`                                    | ➖   | 上传目录，默认 `./data/uploads`，容器内 `/app/data/uploads`                    |
| `UPLOAD_MAX_BYTES`                              | ➖   | 单文件上限，默认 20MB                                                          |
| `SMTP_HOST/PORT/SECURE/USER/PASS/FROM`          | ➖   | 邮件通知；后台「系统设置」里的配置优先级更高                                   |
| `OPENAI_BASE_URL/API_KEY/MODEL/EMBEDDING_MODEL` | ➖   | AI 的首次默认值；后台「AI 助手」里的配置优先级更高                             |
| `WECHATBOT_ENABLED`                             | ➖   | 置 `true` 则服务启动时自动登录微信（等价于后台那个开关）                       |
| `WECHATBOT_STORAGE_DIR`                         | ➖   | 微信登录凭证目录，默认 `${UPLOAD_DIR}/wechatbot`；Docker 里已挂在 `uploads` 卷 |
| `WECHATBOT_DEFAULT_TO`                          | ➖   | 微信默认接收人（wxid 或备注名）                                                |
| `WECHATBOT_PORT/TOKEN`                          | ➖   | 外部桥接服务（`pnpm wechat:bridge`）的参数                                     |

## 项目结构

```
├─ server.ts                    # 自定义 Node server：Next + Socket.IO 同进程
├─ prisma/
│  ├─ schema.prisma             # 完整数据模型（多商家、订阅、通知、跟进与风控）
│  ├─ migrations/               # 增量迁移历史
│  └─ seed.ts                   # 演示数据（幂等，含知识库切片索引）
├─ public/widget.js             # 访客端嵌入加载器（零依赖原生 JS）
├─ scripts/
│  ├─ e2e.mjs                   # 主要端到端验收脚本
│  ├─ smoke-admin-data.mjs      # 后台写入路径的数据层冒烟（12 项）
│  └─ wechatbot-bridge.mjs      # 微信通知桥接（扫码登录 + 单向发送）
└─ src/
   ├─ app/
   │  ├─ admin/                 # 后台管理（站点/客服/会话/话术/AI/通知渠道/设置/日志）
   │  ├─ agent/                 # 客服工作台
   │  ├─ widget/                # 访客聊天界面（iframe 内容页）
   │  ├─ login/                 # 客服与管理员登录
   │  └─ api/                   # REST：auth / agent / widget / admin / files
   ├─ components/
   │  ├─ ui/                    # shadcn/ui 组件
   │  ├─ admin/ · agent/ · widget/
```

## 可观测性

每个 HTTP 请求都会生成独立 `x-request-id`，响应头和 API 错误体中都会返回该编号。服务端以 JSON 行式输出结构化日志，包含请求方法、路径、状态码、耗时和错误信息；密码、Token、Cookie、API Key、数据库连接串等敏感值会在输出前脱敏。日志写入 stdout，可直接交给 Docker、systemd journal 或日志采集系统。

### 数据模型要点

- `Site` = 站点/渠道；`SiteAgent` 做客服与站点的多对多授权（管理员默认全部可见）
- `tenantDb` 在商家读写时额外校验会话、访客、消息、附件、知识库和风控规则的归属关系，并拒绝关键模型的嵌套 relation 写入。
- `Visitor` 以「站点 + 浏览器本地标识」唯一，邮箱在发起会话前必填；
  额外记录访问次数、浏览页数、落地页/当前页、来源与环境指纹（`meta`）
- `Conversation` 上冗余未读数、首响时间、评价，便于列表与统计；`Message` 挂 `Attachment`，
  AI 消息的过程信息（模型、工具轨迹、知识库命中）存在 `Message.meta`
- `AiKnowledge` + `AiKnowledgeChunk`：知识条目与切片（切片可带 embedding 向量）
- `CannedResponse` 支持全局/站点两级；`WebhookEndpoint` 按事件订阅
- `User.preferences` 存客服个人偏好（提示音、音量、桌面通知、AI 模型）
- `AuditLog` 记录后台与登录关键操作

### 实时事件

| 方向 | 事件                                            | 说明                                    |
| ---- | ----------------------------------------------- | --------------------------------------- |
| S→C  | `message:new`                                   | 新消息（含会话快照）                    |
| S→C  | `conversation:created` / `conversation:updated` | 会话新建 / 状态变化                     |
| S→C  | `conversation:read`                             | 对端已读                                |
| S→C  | `typing`                                        | 输入中（访客/客服）                     |
| S→C  | `presence:agent` / `presence:visitor`           | 在线状态变化                            |
| C→S  | `conversation:join` / `conversation:leave`      | 客服加入/离开会话房间（访客走个人房间） |
| C→S  | `typing` / `agent:status` / `visitor:ping`      | 输入中、状态切换、访客心跳              |

房间约定：`conversation:<id>`、`agent:<userId>`、`site:<siteId>:agents`、`visitor:<visitorId>`。
身份与会话访问结果在单个 Socket 连接内短期复用（默认 5 秒），减少输入状态等高频事件的数据库查询；停用、密码变更和角色变更仍会主动断开对应连接。
普通消息同时投递到「会话房间」与「访客个人房间」（访客端不依赖 join 时机）；
**内部备注只发会话房间**，访客既收不到实时事件，也读不到历史里的 `NOTE`。

## 常见问题

**为什么一定要 `pnpm dev` 而不是 `next dev`？**
Socket.IO 挂在自定义 Node server 上（`server.ts`），裸跑 `next dev` 就没有实时通道，
工作台会退化为 15 秒轮询，并在连接恢复时重新同步。另外 `server.ts` 里补了 Next 的运行时基线
（`globalThis.AsyncLocalStorage`），自定义 server 少了它会直接渲染报错。

**没有 Redis 能跑吗？**
能。限流退化为进程内计数、在线状态退化为内存标记，单实例部署完全够用。

**上传文件存在哪？**
默认本地磁盘 `UPLOAD_DIR`（Docker 里是 `uploads` 卷），下载走 `/api/files/<id>`
并做权限校验（客服需站点权限、访客仅限本人会话）。要换对象存储时，只需改
`src/lib/storage.ts` 的读写实现。

**后台地址是怎么来的？**
由 `.env` 里的 `ADMIN_PATH` 决定，默认 `/admin`；建议用随机串（生成方式写在 `.env.example` 里）。
服务启动日志会打印完整地址。改完要重启服务；`/admin` 这条默认路径会直接 404，
所以别忘了自己保存一下新地址。

**AI 会自动回复吗？会不会抢客服的话？**
默认关闭（策略选「关闭」时只在工作台里点「AI 建议」用）。选「客服不在线时自动回复」时，
只要有任何客服在线就交给人工；选「所有访客消息都先自动回复」时，如果人工客服在最近 5 分钟内
还在回复，AI 也不会插话。AI 回复不会把会话算成「已接入」，也不会写入人工首响指标。

**知识库怎么召回？**
条目会先自动切片（约 420 字一片，带重叠），检索时对切片打分：关键词命中权重最高，其次是标题，
再是内容里的词/双字命中；取 `知识库召回条数` 指定的前 N 片（同一篇最多 2 片）拼进系统提示词。
中文不用分词，直接把你希望触发这条内容的词填进「关键词」即可。
在 `/admin/ai` 打开「向量检索（RAG）」并填好向量模型后，还可以点「重建向量索引」：
切片会调用 `/v1/embeddings` 存下向量，检索变成**向量 + 关键词混合**，口语化提问也能命中。
**模型会自己查知识库吗？**
会。打开「工具调用」后，模型可以自行调用 `search_knowledge`、`get_visitor_context`、
`escalate_to_human`、`tag_conversation`；每次调用的参数、结果、耗时都会记在工作台那条
AI 消息的 `meta` 里，点开「工具 / 知识库」小标签就能看到。

**离线留言的邮件没发出去？**
先到 `/admin/settings` 配置 SMTP 并点「保存并测试连接」；站点还要填「通知邮箱」。
两者缺一都不会发信（Webhook 渠道不受影响）。

**能接第三方渠道（微信公众号 / Telegram 收消息）吗？**
当前版本的通知渠道是**出方向**（把事件推给群机器人 / 你的服务 / 个人微信）。
入方向的第三方渠道（公众号、Telegram 收消息回复）需要额外的渠道适配器，属于后续规划——
在入方向打通之前，AI 助手可以先把「无人应答」这一段接住。

**后台点一下要等半天？**
大概率是开发模式的代价，不是实现问题。同一个后台页面实测：**生产 70–220ms**，
开发（已编译）850–1800ms，开发首次访问还要加上 2–4 秒按需编译。
想感受真实速度：`pnpm build && pnpm start`，或用 `docker compose up -d --build`。
另外后台已经加了路由级骨架屏与客户端路由缓存（`staleTimes`），
即便在开发模式下点击也会立刻出现骨架而不是白屏。

**嵌入代码弹窗里的长脚本标签会不会撑破布局？**
不会，代码块会自动折行，复制按钮固定在右侧，窄屏也能正常显示。

**桌面通知没弹出来？**
浏览器只在 HTTPS（或 localhost）下允许 `Notification` 权限；用 http 域名访问时，
站内未读数、提示音仍正常工作，只是不会弹出系统通知。

**提示音没声音？**
浏览器的自动播放策略要求「先有一次用户点击」才允许出声：进工作台后随便点一下页面
（比如点开一次铃铛设置）即可解锁；右上角铃铛里可以换音色、调音量、逐个试听。
音量设为 0% 或选了「静音」预设当然也不会响。声音是 WebAudio 现场合成的，
不需要任何音频文件，也不受 CDN 影响。

## 局域网与反向代理

应用默认监听 `BIND_HOST=0.0.0.0`，不使用操作系统或 Docker 自动设置的 `HOSTNAME`。
局域网使用时将 `APP_URL` 设为实际访问地址（例如 `http://192.168.1.168:3000`）。
复制按钮兼容普通 HTTP；浏览器拒绝自动复制时会显示可手动选择的文本。

IP 限流和访客资料使用自定义 server 根据连接地址生成的 IP。默认忽略客户端提供的转发 IP。
在反向代理后部署时，设置 `TRUSTED_PROXY_CIDRS` 为实际代理的 IP 或网段，例如本机代理使用
`127.0.0.1/32,::1/128`。代理应追加或覆盖 `X-Forwarded-For`；应用从右向左跳过可信代理，
取第一个非可信地址。仅配置代理实际使用的地址。业务入口必须通过 `server.ts`，不要使用裸 `next start`。

## Linux 后台服务

宿主机直接运行 Node 时，可使用用户级 systemd 管理应用；数据库与 Redis 可继续使用 Compose。

```bash
pnpm build
node scripts/install-service.mjs            # 查看将安装的服务配置
pnpm service:install                       # 安装并启用用户服务
pnpm service:status
pnpm service:logs
pnpm service:restart
```

服务启动前执行数据库迁移，异常退出后自动重启，日志写入 systemd journal，由系统管理保留和轮转。
用户已启用 linger 时可以开机运行且不依赖登录会话；可用 `loginctl show-user "$USER" -p Linger` 检查，
需要时由管理员执行 `loginctl enable-linger 用户名`。
更新代码后重新运行 `pnpm build` 和 `pnpm service:restart`。
如使用 `NEXT_DIST_DIR` 隔离构建目录，将它写入 `.env`，构建和服务必须使用同一目录。
宿主机服务和 Compose 的 app 服务二选一，避免争用端口。

## 持久通知队列

迁移 `8_notification_outbox` 新增 `NotificationJob` 表。消息写入、分配/转接和结束会话时，
对应通知任务与业务数据在同一个数据库事务中提交，外部发送不阻塞请求。
应用内 worker 每两秒处理最多四个任务，各 Webhook 目标和邮件独立确认、最多尝试五次；
临时失败按退避时间重试，永久失败标为 `FAILED` 并保存 `lastError`。
进程退出后，未处理任务保留；处理中任务的五分钟租约过期后可被新实例接管。
已送达记录保留七天，失败记录保留三十天。

发送采用至少一次语义：外部服务已接收、但本地确认前崩溃时可能重复。
Webhook 携带稳定的 `x-beesupport-delivery-id`，接收方可据此去重；邮件重试使用相同 Message-ID。
删除或停用的 Webhook 会跳过待发送任务。后台“测试推送/测试发信”仍立即执行，以便检查配置。

回归验证：`pnpm test`，以及在未运行应用 worker 的独立测试数据库上执行
`TEST_DATABASE_URL=... pnpm test:db`；浏览器回归使用连接该测试库的应用实例，执行
`TEST_DATABASE_URL=... TEST_APP_URL=... pnpm e2e:frontend`。

## 聊天体验、访客画像与风控

聊天图片点击后在当前页面放大，支持缩放、重置和 Escape 关闭；嵌入窗口会临时展开到整页，关闭图片后恢复。
客服和访客的输入框均提供表情面板，表情插入当前光标位置，随普通文字消息发送。
站点管理的「打开访客端」会打开响应式示例网页，实际加载本站点的 `widget.js`，便于测试桌面和手机嵌入效果。
预览需要管理员登录，并使用短期、绑定站点的预览令牌；不需要修改正式站点的域名白名单。
预览发送的消息会进入真实工作台。

后台「访客画像」默认展示整体统计：访客数、访问/页面浏览累计值、咨询转化、回访占比、近七天活跃，以及设备、浏览器、系统、语言、来源和标签覆盖分布。
可按站点查看，新增访客趋势支持近 7/30/90 天，日期按北京时间计算；统计覆盖完整数据，不以明细分页的样本推算。
嵌入代码加载后会登记匿名访问，并复用浏览器本地标识在发起咨询时补全身份，不会因匿名登记而跳过站点的邮箱门槛。
匿名上报接口不签发聊天令牌或返回个人档案；每 IP 每五分钟最多 120 次上报，统计可能受浏览器存储/网络阻止影响。
「访客明细」保留站点/身份状态筛选与姓名、邮箱、标签、完整 IP 搜索，可查看访问、设备和历史咨询，维护跨会话的内部标签/备注，封禁身份或跳转 IP 封禁。

后台「风控管理」支持全局或单站点规则：违禁词、IPv4/IPv6 地址及 CIDR 网段，可设置到期时间、批量添加、编辑、停用和删除。
违禁词采用字面包含匹配，忽略大小写、全半角、空白和常见隐形字符，检查访客身份文本、消息、主题、评价及上传文件名；不对图片内容进行 OCR。
IP 规则使用服务端确认的当前连接地址，覆盖新会话、已有访客请求和实时连接，不限制客服和管理员登录。
启用封禁时会断开匹配的现有实时连接。拦截记录保存时间、命中规则、IP 与访客关联，不保存被拒消息的全文；规则变更和画像维护同时写入操作审计。

新增迁移为 `9_visitor_profiles_and_risk`。新功能的实际浏览器/API 回归使用独立测试服务，执行
`TEST_DATABASE_URL=... TEST_APP_URL=... pnpm e2e:features`。

## 图片轰炸防护

站点编辑中新增「图片逐张放行」，默认关闭。开启后，每位访客最多持有一张待放行图片；图片正常显示给客服，客服点击图下的「允许再发一张」后，访客才可继续发送下一张，文字消息不受影响。
名额按访客身份保存在数据库中，换会话、刷新、多标签页、并发上传以及发送开关开启前的旧附件都经过同样校验。
重复批准旧图不会释放新图的名额，客服自己的图片不受这一限制。

上传后发送中断时，访客可重试发送；仅未发送的图片可取消并释放名额，已发送图片不能自行取消限制。
图片消息重试使用稳定标识，避免成功响应丢失导致重复发送。关闭站点开关会解除已有等待限制。
同时保留单文件大小/类型校验、每访客每五分钟 20 次上传上限，并增加每 IP 每五分钟 60 次上传上限，防止不断更换浏览器身份绕过单访客频率限制。
多用户共享同一公网 IP 时会共享 IP 上限。持续骚扰可配合风控中的 IP/身份封禁处理；逐张放行适合高风险站点，开启后需要客服手动操作。

新增迁移 `10_image_review`。验收命令：显式设置获准使用的 `TEST_DATABASE_URL` 后运行 `pnpm test:analytics-images`；再设置 `TEST_APP_URL` 运行 `pnpm e2e:analytics-images`。


## 统一托管版（商家与套餐）

现有数据通过 `z11_hosted_merchants` 迁移归入 `legacy` 默认商家，原管理员继续拥有平台权限；原有客服、站点、访客、会话与附件保留。默认商家的初始额度用于兼容既有数据，正式运营时可在后台调整。新部署使用 `pnpm db:deploy` 后再初始化数据。

- 平台管理员 `ADMIN`：后台「商家与套餐」可人工创建商家、审核申请、设置套餐名称、到期时间、启用账号数、站点数、每月新会话数和存储额度。平台「概览」展示所有商家的统计。
- 商家管理员 `MERCHANT_ADMIN`：管理自己商家的站点、团队、整体访客画像、会话、话术、通知及风控。客服 `AGENT` 继续按授权站点访问。一个登录邮箱对应一个账号/商家，站点标识在平台内唯一。
- `/register` 提交入驻申请，默认待审核；开通后使用管理员邮箱登录。平台也可在后台直接创建并开通。当前版本采用人工套餐开通和续期。
- 「商家配置与用量」查看套餐及真实用量，编辑窗口标题、外链 Logo、主题色、按钮位置、底部品牌文字、图片/文件/表情/评价开关及单个附件大小。配置按「平台默认 → 商家默认 → 单站点覆盖」生效，逐项勾选覆盖或恢复继承，支持电脑/手机预览。原有欢迎语、工作时间、邮箱门槛、自动分配及图片逐张放行仍在站点编辑中配置。
- 附件大小还受实例 `UPLOAD_MAX_BYTES` 硬上限约束；访客功能开关在服务端再次校验。Logo 由浏览器直接加载，请使用访客可以访问的图片地址。
- 启用账号额度包含商家管理员，不包含平台管理员；站点额度包含停用站点；存储包含未发送的附件；会话额度统计北京时间自然月新建的会话，已有会话继续收发不重复计费。配额在数据库事务中锁定商家行，防止并发超额。
- 到期后暂停访客接待及新资源消耗，保留历史数据和商家后台查看/续期入口；停用商家撤销员工令牌并断开实时连接。人工续期后恢复接待。
- SMTP、AI 服务密钥及内置个人微信机器人由平台统一管理。商家的 Webhook 只能使用公网 HTTPS 443 地址，实际发送时固定已验证的 IP，不跟随重定向，避免访问平台内网。历史默认商家渠道兼容原有内网测试地址。
- 站点、会话、附件下载、Socket 房间、共享话术/知识库/风控/通知和统计查询均限制商家范围。「全部站点」共享配置属于对应商家；平台创建未指定站点的共享配置属于默认商家。

验证：`pnpm test`；显式指定获准测试的 `TEST_DATABASE_URL` 后运行 `pnpm test:tenants`，另设置 `TEST_APP_URL` 后运行 `pnpm e2e:tenants`。浏览器测试需要安装 Playwright Chromium 或设置 `PLAYWRIGHT_EXECUTABLE_PATH`；脚本只清理自己创建的临时商家及站点。新版不包含自动支付、自定义后台域名和代理商体系。


## 套餐、续费订单与运营管理

新增迁移 `z12_subscription_orders`，只新增套餐和订单表，保留当前商家及其额度、有效期。平台后台新增「套餐管理」「订单审核」，商家后台新增「套餐与续费」。系统不预置付费套餐，运营者自行填写价格（人民币，精确到分）、有效天数、账号/站点/月会话/存储额度，并决定是否上架。

商家选择套餐并确认价格、额度与有效期规则后提交订单。报价有效 7 天，每个商家同时只允许一笔有效待确认订单。订单保存提交时的价格和额度快照；之后编辑或下架套餐不改变已提交的有效报价。商家可取消待确认订单，平台可拒绝并反馈原因，或核对收款后确认开通。付费订单确认必须填写仅平台可见的收款凭据，同一凭据不能重复用于其他已开通的付费订单。

确认开通在同一数据库事务中更新商家额度、有效期、订单状态和审计记录。尚未到期的从原到期日顺延；已到期或原来长期有效的从确认当天开始，购买前及确认时均有规则提示。新额度即时生效，不重置北京时间自然月已使用的会话数。商家未开通/已停用、报价过期或现有用量超过新套餐额度时不能确认。重复提交与并发确认具有幂等保护，取消与确认只能有一方成功。

「商家配置与用量」显示 7 天内到期和达到 80% 用量的页面提示，并提供续费入口。平台商家列表改为服务端搜索、状态筛选及分页，支持搜索全部商家的名称、标识和联系邮箱；每页批量统计用量，避免按商家逐个重复查询。订单列表支持订单号/商家搜索、状态筛选和分页。

当前仍为人工收款核对与开通，不会调用支付渠道或自动扣费。接入自动支付时需另行配置真实商户参数，并使用签名验证的支付回调驱动确认流程。

验证命令：显式指定获准测试的 `TEST_DATABASE_URL` 后运行 `pnpm test:subscriptions`；再指定 `TEST_APP_URL` 运行 `pnpm e2e:subscriptions`。脚本只创建和清理自己的临时商家、套餐、订单及相关审计记录。

## 首页与悬浮按钮外观

首页提供产品能力介绍、交互外观体验、接入步骤、常见问题，以及入驻和账号登录入口。首页体验区仅运行本地示例对话，不创建访客、会话或发送通知；其内容与后台演示数据无关联。首页不公开随机后台路径，账号登录后按权限进入对应工作区。

在「平台默认配置」「商家配置与用量」或站点编辑的「访客窗口品牌与功能」中，可以选择经典圆形、圆角方形、文字胶囊、轻盈描边、柔和底色、品牌头像六种悬浮按钮。新增 `launcherStyle` 和 `launcherLabel` 配置，继续采用平台 → 商家 → 单站点继承，无需数据库迁移。按钮文案最多 20 字，文字样式留空时显示「在线客服」；品牌头像使用同一 Logo 地址，未配置或加载失败时显示耳机图标。文字颜色自动适应主题色。

真实站点预览使用保存的按钮样式与文案。既有嵌入代码的 `position`、`color`、`label` 参数继续优先，亦可用 `style=bubble|rounded|pill|outline|soft|avatar` 单独指定外观；通常无需修改原嵌入代码，重新打开页面即可获取配置。配置不接受自定义 HTML/CSS。

头像样式保持圆形；原代码中的 `label` 仍作为按钮的无障碍名称，不会把头像扩成文字胶囊。

## 接入向导、首页运营与到期提醒

新增迁移 `z13_onboarding_and_notices`，仅为站点增加最近嵌入上报记录，并新增账号通知表及到期查询索引。人工收款、订单审核和套餐开通方式保持原有流程。

新商家没有站点时，登录后进入「接入向导」。向导按所选站点展示建站、试聊、真实接入三步进度；试聊以实际访客消息为准，正式接入以嵌入窗口成功上报为准。后台签名预览和未携带有效嵌入上下文的匿名 API 请求不会标记正式接入。接入来源由服务端验证的签名上下文获得，不主动抓取商家网页。商家可复制专属代码、打开真实预览或工作台，并刷新检测结果；添加客服为可选操作，商家管理员也能直接接待。未完成基础接入时，概览页保留继续向导入口。

平台「首页运营配置」可编辑首页品牌、SEO 描述、首屏/页尾文案、六张能力卡片、常见问题、区块开关，以及最多六个公开展示套餐。默认不展示任何套餐；只展示明确选择且仍上架的套餐，价格和额度跟随套餐管理更新。编辑后先保存草稿，再查看仅平台可访问的 `/home-preview` 全宽预览，最后发布；公开首页只读取已发布内容。草稿与发布操作带版本检查、事务锁和审计，避免并发覆盖。恢复默认内容也需要保存并发布才会影响公开页面。配置只接受有限文本和结构化字段，不接受自定义 HTML、脚本或任意跳转链接。

「通知中心」按账号隔离，支持已读标记。默认启用站内到期提醒，邮件默认关闭；平台可在「到期提醒」中关闭提醒、选择提前 7/14/30 天或开启邮件。后台每分钟检查一批最多 200 个商家并轮转，长期有效、待审核及停用商家不提醒。到期前符合范围的 30/14/7/3/1 天阶段各生成一次，到期后 7 天内补发一次；新启用功能时只补当前阶段，不追发所有旧阶段。同一账号、同一有效期和阶段由数据库唯一键去重。

续期后，旧有效期通知自动隐藏；邮件经事务发件箱重试，发送前再次核对有效期、商家状态、账号角色/归属及提醒配置，失效任务会跳过。邮件开启但未配置 SMTP 时，站内通知正常生成，配置可用后按当前阶段补充邮件任务。邮件是至少一次投递，SMTP 已接受但投递结果未落库时仍可能重试；固定 Message-ID 便于收件端识别。通知与邮件不会自动收款或开通套餐。

验证：`pnpm test`；显式选择获准测试库后运行 `pnpm test:growth`，另设 `TEST_APP_URL` 后运行 `pnpm e2e:growth`。验收会暂存并恢复首页草稿/发布及提醒配置，临时更改仅适用于获准的测试环境；只清理自身的商家、账号、站点、套餐、通知与审计，持久演示数据保留。邮件队列测试使用隔离的 SMTP 替身和未来可用时间，不向真实邮箱发信。

## 人工收款流程

新增迁移 `z14_manual_collection`，为订单增加商家付款反馈时间、说明和版本号。平台「收款配置」可设置说明、联系方式和可选的收款码图片地址，默认关闭展示。收款信息只在登录后的套餐与续费页面展示，不向公开首页或访客窗口下发。二维码由浏览器加载，服务器不抓取图片地址。配置保存包含权限检查、并发版本校验、事务和审计。

## 账号找回、团队邀请与邮箱验证

新增迁移 `z16_account_access`。登录页提供「忘记密码」及重新发送验证邮件入口；找回邮件链接有效期 30 分钟，验证邮件 24 小时，团队邀请 72 小时。打开链接只展示确认页面，提交后才消费令牌。令牌以 256 位随机数生成，账号令牌表只存 SHA-256 摘要；邮件队列用 `AUTH_SECRET` 派生密钥进行 AES-256-GCM 加密，投递完成后清空凭据。链接使用 URL fragment，避免令牌随页面 GET 请求进入服务器访问日志。邮件仍可能因至少一次投递而重复收到，但同一令牌只能成功提交一次。

重置密码会增加 `tokenVersion` 并断开客服连接，使旧登录会话及此前签发的找回链接失效。找回及重发验证接口对不存在、停用、已验证及未配置邮件服务的邮箱返回相同提示，按 IP 每小时 10 次、邮箱每小时 3 次控制发信申请，另有接口总请求限制。链接过期、跨用途使用或账号状态变化均会在提交时重新检查；不会通过找回密码自动开通或重新启用商家/账号。

平台「系统设置」新增「新入驻账号必须验证邮箱」，默认关闭，启用前必须配置 SMTP；只对之后自主申请入驻的账号生效。已有账号、管理员直接创建的账号继续沿用原来的登录方式。关闭开关不会取消已要求验证的账号的要求；可以重新申请验证邮件。验证邮箱并不替代平台审核。管理员原有重置密码入口保留，管理员重置会取消该账号的验证前置要求，但不会伪造邮箱已验证状态。通过邮件找回密码或接受邮件邀请可确认邮箱持有权。

「客服账号」新增团队邀请，可选择客服或团队管理员及授权站点，并支持重发、撤销。平台管理员的邀请也只加入其当前团队，不授予平台管理员角色。邀请不预占账号额度，接受时与其他创建账号操作锁定同一商家行，重新核对有效期、启用状态、邀请人权限和站点归属；并发接受不会突破套餐上限。一个邮箱只能对应一个账号，不会覆盖已有账号密码或转移账号归属。未配置 SMTP 时，页面说明使用手动创建/管理员重置入口；账号邮件发送失败会重试，不会将缺少 SMTP 当作成功投递。请确认 `APP_URL` 是收件人能够访问的完整地址。

## 通知投递管理

迁移 `z17_delivery_management` 为通知任务增加累计尝试次数、人工重试次数和处理结果，并补齐列表查询索引。平台管理员在「系统设置 → 通知投递管理」查看邮件及 Webhook 队列，支持近 7/30/90 天、类型、状态、任务编号筛选与分页。统计使用同一数据库快照，状态卡片遵循时间、类型和编号筛选，不跟随状态筛选变化。页面同时检测数据库、Redis，并显示 SMTP 是否已配置及长时间未处理任务数；SMTP 配置存在不代表目标服务可达，可在系统设置中测试发信。

新任务区分「已投递」「已跳过」，历史已处理任务保留原记录并标记「历史已处理」，不推定其实际发送结果。「已投递」表示邮件服务器或通知渠道接受了请求，不保证最终送入收件箱。渠道已删除、停用、事件取消订阅、账号链接过期或提醒条件变化时记录跳过。未配置 SMTP 的会话邮件会重试并保留失败记录，不再把未发送的邮件当作完成。处理完成的账号邮件会清空队列中的加密凭据，过期链接不会通过重试自动续期。

只有失败任务可人工重试，每轮自动尝试最多 5 次，人工重试保留累计次数并增加审计记录。操作要求平台权限、显式确认及版本校验；并发操作只排队一次，发送中或等待自动重试的任务不能再次排队。重新排队前检查 SMTP 配置、账号链接、提醒当前条件和 Webhook 渠道/事件/站点归属；实际发送时仍会再次检查。重试属于至少一次投递，收件方可能收到重复通知，沿用原任务 Message-ID/投递标识协助去重。人工重试限每管理员每 10 分钟 30 次。

商家及客服不能查看投递管理页或调用平台重试操作。列表不读取通知正文，也不下发收件地址、渠道 URL、令牌、加密凭据、租约或原始错误响应，只显示固定的错误分类。已处理任务保留 7 天、失败任务保留 30 天，筛选较长日期范围不延长保留时间。

### 数据导出与审计检索

## 快捷话术分类与权限修复

## 会话跟进待办

迁移 `z19_conversation_followups` 新增独立的会话跟进记录，包含内部事项、负责人、到期时间、状态和版本。同一会话保留一条跟进记录，完成、取消后可重新安排并递增版本，历次管理操作保留审计。任务随会话删除而删除；删除负责人只清空负责人，保留任务供管理员重新分配。原有会话、消息和离线留言保持不变。

工作台会话顶部「会话跟进」可为待接入、进行中或已结束的会话安排后续处理。手机顶部的转接、结束/重新打开操作使用带无障碍名称的图标，保留访客名称的显示空间；待接入标签及选中会话文字提高了对比度。普通客服只能为自己安排和处理任务；同站点其他客服可查看当前任务了解协作进度，但不能修改。管理员可指定该商家启用中的管理员，或具有该站点权限的客服；不允许跨商家或指定停用、未获授权成员。跟进时间按北京时间输入，须在现在之后、365 天以内。跟进事项最多 1,000 字，仅内部可见，不写入访客消息或导出正文。完成任务不会自动结束会话，结束会话也不自动完成跟进。

后台「客服业务 → 会话跟进待办」提供待跟进、已到期、今日、已完成、已取消筛选，支持关键词、站点、全部/本人任务及每页 20 条的分页。普通客服可从工作台顶部时钟入口进入 `/agent/follow-ups`，仅列出自己负责且仍有站点权限的任务；管理员可查看权限范围内的全部任务。在列表内保存或处理任务后重新加载当前筛选结果，及时更新任务和统计。工作台保存后直接刷新任务详情与到期数量。统计遵循关键词、站点、负责人筛选，不随状态筛选变化。今日待办按北京时间当天计算，包含当天已到期任务；已到期指仍待处理且截止时间不晚于当前时刻。

工作台顶部显示本人已到期数量，在工作台可见时每 30 秒检查，窗口重新获得焦点、恢复可见或当前页面修改任务后会刷新。该提示为站内待办计数，无需 SMTP；此版本不发送跟进邮件或访客消息。离线留言默认由客服主动安排跟进，也可按下节开启站点自动规则。任务处理使用会话行锁、版本校验和事务审计，避免并发重复创建或旧页面覆盖。普通客服失去站点权限后不会继续看到该站点的任务，管理员可重新分配。

## 离线留言自动跟进

迁移 `z20_offline_followup_rules` 增加站点内部规则。从后台「会话跟进待办 → 自动跟进规则」进入，选择站点后配置开关、默认负责人及 1～10,080 分钟（7 天）的处理时限。平台管理员可管理全部站点，商家管理员仅管理自己的站点；普通客服无权读取或修改规则。新站点及现有站点默认关闭，不自动迁移或启用配置。

开启后，新建的离线会话在同一事务内生成一条内部跟进，到期时间为会话创建时间加处理时限。离线状态由服务端根据工作时间和在线客服判定，不信任访客提交的来源。已有会话续发消息、消息重试及并发处理不会重复创建，不覆盖人工安排或重新打开已完成任务；历史留言不补建。修改规则只影响之后新建的离线会话，关闭规则保留已有任务。任务与人工跟进使用同一列表、工作台到期计数及权限规则，不改变会话接待状态，也不额外发送访客消息或邮件。

负责人必须为同商家启用的管理员，或获得本站点授权的客服。负责人被停用、删除或移除站点权限后，规则暂停创建任务；配置页提示负责人不可用，管理员可重新选择或关闭规则。规则保存使用站点行锁与版本校验，旧页面冲突后须显式重新加载。规则修改和自动建任务均保留审计；自动任务审计记录规则版本及负责人，不记录访客正文。审计失败会回滚对应事务。配置独立存储，不进入公开 widget 配置。

验证：`pnpm test:auto-follow-ups`、`pnpm test`、`pnpm lint` 和生产构建；设置获准的 `TEST_DATABASE_URL`、`TEST_APP_URL` 及 `ACCOUNT_E2E_BUILD` 后运行 `pnpm e2e:auto-follow-ups`。隔离验收覆盖真实配置表单、访客会话接口、商家和负责人权限、首次/更新并发、重复请求、历史及人工任务保留、负责人失效、事务回滚，以及手机亮暗主题无障碍检查；不向外部发送邮件，结束清理临时数据库。后续效率看板等按 [项目改进计划](ROADMAP.md) 逐步实施。

## 长时间未回复提醒

迁移 `z21_unanswered_reminders` 为会话增加当前人工回复等待轮次，并新增独立的站点规则和提醒记录。原会话不回填等待时间；所有站点的提醒默认关闭。从后台「会话跟进待办 → 自动跟进规则」选择站点，在「长时间未回复提醒」中独立设置开关、1～10,080 分钟的等待时长、提醒对象及默认负责人。提醒对象可选择优先当前接待客服（失效或无人接待时使用默认负责人），或始终提醒默认负责人。负责人须为同商家启用的管理员，或获得该站点授权的客服。

第一条尚未获得人工回复的访客消息开始计时，后续补发消息、重试、已读操作、内部备注及 AI 自动回复不会重置或结束本轮。客服公开发送文本、图片或文件后，等待状态和已生成提醒在同一事务内清除；结束会话也会结束提醒，单纯重新打开会话不会重新计时。之后访客再次发消息才开始新一轮。新开启或重新开启规则时只检查此后开始的轮次，不补发之前的等待。调整时长或接收人影响尚未生成的提醒，已生成记录保留原接收人；关闭规则会将未结束的记录归档为「规则已关闭」。原有手动跟进及离线留言自动待办独立保留。

自定义服务启动可优雅停止的定时任务：正常每 30 秒扫描一次，每批最多 100 条，存在下一页时 1 秒后继续。候选查询在数据库比较各站点时限和启用时间，避免历史与未到期轮次占满批次；每条事务重新检查会话、规则、商家有效期和接收人权限。会话行锁、规则共享锁及轮次唯一索引共同防止并发重复提醒和关闭规则后新插入提醒。生成提醒及其审计原子提交，审计不保存消息正文。

工作台顶部铃铛显示发给本人且仍有站点权限的待回复数量，复用现有 30 秒可见页面轮询，窗口聚焦及当前页面回复、附件发送或会话操作后刷新。铃铛进入 `/agent/unanswered`；后台跟进列表也有「未回复提醒」入口，可按站点、关键词、接收人和提醒状态筛选，每页 20 条。管理员查看权限范围内的记录，普通客服只查看自己的提醒；站点、商家或规则暂停时不计入待回复。列表提供等待开始、提醒及结束时间与会话处理入口，时间为北京时间。提醒仅在站内展示，不写入访客消息，也不额外发送邮件或 Webhook。

验证：`pnpm test:unanswered`、`pnpm test`、`pnpm lint` 和生产构建；设置获准的 `TEST_DATABASE_URL`、`TEST_APP_URL` 及 `ACCOUNT_E2E_BUILD` 后运行 `pnpm e2e:unanswered`。隔离数据库验收覆盖实际配置和工作台回复、到期边界、等待轮次、接收人优先级、权限失效、并发去重、版本冲突、关闭与重新开启、审计回滚、100 条游标批次、列表分页以及手机亮暗主题，不向外部发送邮件，结束删除临时数据库。
